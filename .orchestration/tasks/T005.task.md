# T005 — Phase 2 (gateway): 安定性・正確性修正とテスト負債解消

Repo: /Users/mryfmo/Workspace/HerdDeck-0.2.0
背景: 監査計画書の M-G1, M-G3, M-G4, M-G5, M-G6 とテスト構造欠陥(router / MissionOrchestrator.start 未テスト)。

## 修正内容(すべて必須)

### 1. M-G1: `gateway/src/herdr-client.mjs` snapshotFingerprint

fingerprint 入力から揮発フィールドを除去する(少なくとも pane の `scroll` オブジェクト全体。他に出力のたび変わるフィールドがあれば同様に除去し、除去対象をコメントで列挙)。実測: エージェント出力中は 4 秒間に snapshot 5 回・herdr-event 282 件配信されていた。修正後は「出力だけが流れている間は snapshot 再配信されない」こと。

### 2. M-G3: `gateway/src/workflow.mjs` 起動時の stale mission 処理

`resumeRunning()`(または起動経路)で `status === 'starting'` の mission を `failed`(error: 'gateway restarted during start')へ遷移させ、`mission` SSE を publish。

### 3. M-G4: `gateway/src/router.mjs` rate limit

`limiter.allow()` を authorize より前に移動し、limiter key から定数の token fingerprint を除去(source address ベースへ)。認証失敗リクエストも消費すること。

### 4. M-G5: `gateway/src/router.mjs` エラーマッピング

`HerdrRpcError` に herdr エラー種別 →HTTP status のマップを導入(`pane_not_found`/`not_found` 系 →404、`invalid_*`→400、その他 →502)。error envelope の `code` は常に文字列化。

### 5. M-G6: `gateway/src/mosh-manager.mjs` セッション記録

書き込み専用で無限成長する session map に TTL(例: 10 分)での自動削除を実装(setInterval + unref、または作成時の遅延削除)。外部 API は変えない。

### 6. テスト追加(`gateway/tests/`)

- router: 認証(401)、rate limit(429、認証失敗リクエストでも消費されること)、HerdrRpcError→404/400 マップ、code 文字列化、`/healthz` 無認証
- workflow: `starting` mission が起動時に `failed` へ遷移すること
- herdr-client: scroll のみ変化した snapshot で fingerprint が不変であること
