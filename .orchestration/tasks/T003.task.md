## Objective

存在しない `api.sh` に依存して全滅している AGMSG 読取系を repo 内アダプタで復旧し、Gateway をプロセス死させる 3 経路を封鎖する。既存 API の外形(エンドポイント、レスポンス形)は変えない。

## 修正内容(すべて必須)

### 1. C-4: 新規 `gateway/scripts/agmsg-api.sh`(読取アダプタ)

`api.sh` と同じ CLI 契約を実装する bash script(bash + sqlite3 + python3 のみ、依存追加禁止):

- `agmsg-api.sh get teams` → team 名を 1 行 1 JSON 文字列で出力(`"team-name"`)
- `agmsg-api.sh get teams <team> members` → `<agmsgRoot>/teams/<team>/config.json` の member を JSONL で出力(name/type/project を含む object)
- `agmsg-api.sh get teams <team> messages --limit N [--agent A] [--before-id B]` → JSONL、各行 `{"type":"message","id":<int>,"team":"...","from":"...","to":"...","body":"...","at":"<created_at>"}`(id 降順ではなく id 昇順で出力)
- データ源: teams は `<agmsgRoot>/teams/*/config.json`。messages は sqlite3 を **read-only**(`file:...?mode=ro` + `-readonly`)で `messages` テーブルから取得(schema: id, team, from_agent, to_agent, body, created_at, read_at)。DB パスは `AGMSG_STORAGE_PATH` があれば `$AGMSG_STORAGE_PATH/messages.db`、なければ `<agmsgRoot>/db/messages.db`
- `--agent A` は `to_agent = A OR from_agent = A` でフィルタ、`--before-id B` は `id < B`
- JSON エスケープは sqlite3 の `-json` 出力を python3 で JSONL 化するなど、正しさ優先で(手組み文字列連結での JSON 生成は禁止)
- agmsgRoot は第一引数でなく環境変数 `AGMSG_ROOT` で受け取る(agmsg-client.mjs 側で渡す)
- shdoc 形式のヘッダコメント(@file/@brief/@description/@arg/@example)を付ける

### 2. C-4: `gateway/src/agmsg-client.mjs` の読取経路切替

- `teams()/members()/messages()` と preflight の `api.sh` 参照を repo 内 `gateway/scripts/agmsg-api.sh` に変更(呼び出し時に env `AGMSG_ROOT=<this.root>` を渡す)。**書き込み系(send.sh/join.sh/delivery.sh)は従来どおり `<agmsgRoot>/scripts/` の公式 script を使う**
- preflight の required リストを実在に合わせる: 公式側 `send.sh join.sh delivery.sh` + repo 側 `agmsg-api.sh`

### 3. H-G1: runtime whitelist の整合

- `agmsg-client.mjs` join の whitelist を join.sh の実 case リスト `['claude-code','codex','gemini','antigravity','copilot']` に変更
- `config.mjs` の profile runtime 検証から `'other'` を削除し、config load 時点で上記 5 種以外を明示エラーにする(mission 起動時まで遅延させない)

### 4. C-5: `workflow.mjs` `#reconcileSnapshot`

mission ごとの agmsg 読取(`this.agmsg.messages(...)`)を try/catch し、失敗時は `explicitCompletion = false` として herdr ステータスフォールバックを継続。失敗は `audit.failure`(それ自体も throw させない)+ `gateway-warning` SSE に格下げ。1 mission の失敗が他 mission の reconcile を止めないこと。

### 5. M-G7: `workflow.mjs` delivery assist tick

catch 内の `audit.failure` を try/catch でガードし、連続失敗時は指数バックオフ(上限 60s)で audit 追記を抑制。timer 再アームがどの経路でも必ず行われること。

### 6. H-G2: `gateway/src/sse.mjs`

`SseHub.add` で `response.on('error', () => <client除去>)` を登録。write 失敗時の除去経路と二重除去にならないよう注意。

### 7. H-G3: `gateway/src/router.mjs`

`X-Request-ID` の読取・`setHeader` を try ブロック内へ移動し、値を sanitize(`/^[A-Za-z0-9._-]{1,128}$/` 以外は randomUUID に差替)。

### 8. テスト差替・追加(`gateway/tests/`)

- `agmsg-client.test.mjs`: 捏造 `api.sh` フィクスチャを廃止し、実アダプタ `gateway/scripts/agmsg-api.sh` を temp AGMSG_ROOT(temp teams config + temp sqlite db を作って)に対して実行する統合テストへ差替
- `workflow.test.mjs`: `controlAgmsgName` **有り** + agmsg.messages が throw する状況で herdr フォールバック完了が機能するテストを追加(C-5 の再発防止)
- 既存テストは全維持(EPERM で落ちる herdr-client.test.mjs はサンドボックス起因なので触らない)
