## Objective

一切イベントを配信できない SSE クライアントを、SSE 仕様どおり空行境界でディスパッチする手動フレーミングに置き換え、再接続ループの寿命・バックオフ欠陥を直す。

## 修正内容(すべて必須)

### 1. C-1: `iOS/HerdDeck/Networking/GatewayClient.swift` の SSE 読取

- `bytes.lines` の使用をやめる(AsyncLineSequence は空行を produce しないためイベント境界を検出できない)
- `URLSession.AsyncBytes` からバイト単位で読み、`\n` で行分割(末尾 `\r` は strip、`\r\n` 対応)する **`SSEFrameParser`**(小さな internal struct、`feed(byte:) -> [GatewayEvent]` 相当の純ロジック)を同ファイル内に実装し、空行=イベント確定・`event:`/`data:` 蓄積・複数 data 行の `\n` 結合という現行意図を維持
- 行長・累積 data サイズに上限(例: 1 行 256 KiB / イベント 1 MiB)を設け、超過時はそのイベントを破棄して継続(無限成長の防止)
- ストリーム終端時に未確定バッファは破棄(SSE 仕様どおり)

### 2. M-I5: `iOS/HerdDeck/App/AppState.swift` の SSE ループ

- `guard let self else { return }` でループ全体を strong 保持している構造をやめ、イテレーション単位で weak → strong 昇格し直す(deinit 可能に)
- イベントを 1 件でも受信したら `retryDelay` を初期値(1s)へリセット
